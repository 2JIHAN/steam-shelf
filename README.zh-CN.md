Steam Shelf 把已安装的 Steam 游戏以封面图网格呈现。点击封面即可开始游戏。再点一下，它会为每款游戏在 `~/Applications` 生成真正的 `.app`，于是游戏能像其他应用一样从启动台和聚焦搜索打开。

## 功能

- **封面图网格** —— 读取 Steam 已存在磁盘上的封面。Steam 没有封面的游戏显示为标题卡片。
- **一键启动** —— 打开 `steam://rungameid/<appid>`，云存档、游戏时长和覆盖层照常工作。
- **逐游戏 `.app` 快捷方式** —— 附带封面图标，可直接从启动台和聚焦搜索启动。
- **安全清理** —— 已卸载游戏的快捷方式移到废纸篓，且只处理 Steam Shelf 能确认由自己管理的包。
- **实时跟随** —— 安装或删除游戏后无需重启即可刷新。
- **多库支持** —— 包括外置硬盘。
- **搜索与排序** —— 按最近游玩、名称或占用空间。
- **四种语言** —— English、한국어、日本語、简体中文。
- **不使用网络** —— 不建立任何连接。详见下文。

## 安装

从[最新发行版](https://github.com/2JIHAN/steam-shelf/releases/latest)下载 `SteamShelf-x.y.z-universal.zip`，解压后把 **Steam Shelf.app** 拖到「应用程序」文件夹并打开。

### 从源码构建

```bash
git clone https://github.com/2JIHAN/steam-shelf.git
cd steam-shelf
./build.sh                        # → ~/Applications/Steam Shelf.app
./build.sh /Applications          # 安装到别处
ARCHS=arm64 ./build.sh            # 跳过 Intel 切片
```

需要 Swift 6（Xcode Command Line Tools）。打包签名的发行版：`NOTARY_PROFILE=<notarytool 配置名> ./release.sh`。

## 使用

| 操作 | 效果 |
|---|---|
| 点击封面 | 启动游戏 |
| 右键封面 | 启动 · 打开安装目录 · 打开商店页面 · 复制 AppID |
| <kbd>⌘</kbd><kbd>R</kbd> | 重新加载游戏库 |
| <kbd>⇧</kbd><kbd>⌘</kbd><kbd>S</kbd> | 同步快捷方式 |
| 搜索框 | 按游戏名筛选 |
| 排序菜单 | 最近游玩 · 名称 · 占用空间 |

## 快捷方式同步

按 <kbd>⇧</kbd><kbd>⌘</kbd><kbd>S</kbd>，每款已安装游戏都会在 `~/Applications` 得到一个 `.app`，图标由封面生成。文件名中的非法字符会被替换，`Hollow Knight: Silksong` 变成 `Hollow Knight - Silksong.app`。

同步只把两类包视为自己的产物：

| 类型 | 识别方式 |
|---|---|
| Steam Shelf 创建的 | `Info.plist` 中的 `SteamShelfAppID` 键 |
| Steam「Add to Applications」创建的 | `run.sh` 中的 `autogenerated file` 标记及 `steam://run` 链接 |

`~/Applications` 中的其他应用一概不动。如果某个普通应用已占用游戏想用的名字，该游戏会被跳过并在结果中列出，而不会被覆盖。已卸载游戏的快捷方式进入废纸篓，可以恢复。

## 不使用网络

Steam Shelf 不会建立任何网络连接。这一点由 [stays local](https://github.com/2JIHAN/stays-local) 认证——它在自己的 CI 中构建本仓库，并扫描包内每一个 Mach-O。它只读取磁盘上 Steam 的文件，并通过 URL scheme 启动游戏，没有任何数据外发，也没有遥测、更新检查或封面下载。

你可以自己验证——与徽章依据的是同一项检查：

```bash
git clone https://github.com/2JIHAN/stays-local.git
./stays-local/verify.sh /path/to/steam-shelf --runtime
```

| 层 | 检查 |
|---|---|
| 源码 | 没有 `URLSession`、`NWConnection` 或套接字；没有白名单之外的远程地址 |
| 二进制 | 未链接 `CFNetwork` 和 `Network.framework`，未引用网络相关符号 |
| 运行时 | 运行中的应用打开的套接字为 0 |

关键在于二进制这一层。源码 grep 可以绕过，但只要代码触达网络，无论怎么写都会引入 `CFNetwork`，而它会出现在 `otool -L` 中。CI 在每次 push 时运行静态检查。

白名单里只有一个地址——右键菜单**打开商店页面**使用的 `store.steampowered.com`。它通过 `NSWorkspace` 把 URL 交给浏览器，应用自身不会连接。

## 支持的语言

界面跟随系统语言，未覆盖的语言回退到英语。若要新增语言，把 `Resources/en.lproj/Localizable.strings` 复制到 `Resources/<语言代码>.lproj/`，只翻译每行等号右侧的内容，再把语言代码加入 `build.sh` 的 `CFBundleLocalizations`。无需改动 Swift 代码。

## 常见问题

### Steam 需要保持运行吗？

需要。Steam Shelf 会请求 Steam 启动游戏，与在客户端点击「开始游戏」完全一致，云存档、成就、游戏时长和覆盖层因此都能正常工作。若 Steam 未运行，它会自动启动。

### 执行「同步快捷方式」安全吗？

只有带 Steam Shelf 标记或 Steam 自身 autogenerated 标记的包才会被移除，而移除是移到废纸篓。除读取 `Info.plist` 外不会碰其他应用。

### 支持非 Steam 游戏吗？

不支持。Steam Shelf 读取 Steam 的清单，因此只显示通过 Steam 安装的游戏。位于第二库或外置硬盘上的 Steam 游戏可以正常使用。
