Steam Shelf はローカルの Steam ライブラリを読み取り、インストール済みのゲームをカバーアートのグリッドで表示します。タイルをクリックすれば、そのままプレイできます。もう一度クリックすれば、ゲームごとに本物の `.app` バンドルを `~/Applications` に書き出すので、Launchpad や Spotlight から他のアプリと同じようにゲームを起動できます。Steam のウィンドウを経由する必要はありません。

サードパーティ依存のない単一の SwiftUI バイナリで、`swiftc` 一回でビルドできます。開くべき Xcode プロジェクトもありません。

## 特徴

- **カバーアートのグリッド** — Steam 自身のローカルキャッシュを利用するためオフラインでも動作します。存在しないアートのみ Steam CDN から一度だけ取得してキャッシュします。
- **ワンクリック起動** — タイルは公式の起動経路である `steam://rungameid/<appid>` を開きます。クラウドセーブ、プレイ時間、オーバーレイはすべて通常どおり機能します。
- **ゲームごとの `.app` ショートカット** — インストール済みのゲームをカバーアートのアイコン付きで `~/Applications` に同期します。Launchpad と Spotlight からすぐ起動できます。
- **安全なクリーンアップ** — アンインストール済みゲームのショートカットは完全削除ではなくゴミ箱へ移動します。Steam Shelf が自分の管理下だと確認できたバンドルにしか触れません。
- **ライブラリの自動追従** — `steamapps` フォルダを監視しているため、ゲームの追加・削除は再起動なしでグリッドに反映されます。
- **複数ライブラリ対応** — `libraryfolders.vdf` をたどり、外付けドライブやセカンダリライブラリも読み込みます。
- **検索と並べ替え** — 名前で絞り込み、最終プレイ・名前・使用容量の順で並べ替えます。

## インストール

ソースからビルドします。

```bash
git clone https://github.com/2JIHAN/steam-shelf.git
cd steam-shelf
./build.sh
```

`~/Applications/Steam Shelf.app` に配置されます。別の場所に入れる場合はパスを渡してください。

```bash
./build.sh /Applications
```

ビルド成果物は ad-hoc 署名されます。自分でコンパイルしたものには隔離属性が付かないため、Gatekeeper に阻まれることはありません。zip やダウンロードを経由してアプリを移動した場合は、次のコマンドで属性を外してください。

```bash
xattr -dr com.apple.quarantine "/Applications/Steam Shelf.app"
```

## 使い方

| 操作 | 動作 |
|---|---|
| タイルをクリック | ゲームを起動 |
| タイルを右クリック | 起動 · インストールフォルダを表示 · ストアページを開く · AppID をコピー |
| <kbd>⌘</kbd><kbd>R</kbd> | ライブラリを再読み込み |
| <kbd>⇧</kbd><kbd>⌘</kbd><kbd>S</kbd> | ショートカットを同期 |
| 検索フィールド | ゲーム名で絞り込み |
| 並べ替えメニュー | 最終プレイ · 名前 · 使用容量 |

## ショートカット同期

<kbd>⇧</kbd><kbd>⌘</kbd><kbd>S</kbd> を押すか、ツールバーのボタンをクリックすると、インストール済みゲームごとに `.app` バンドルが `~/Applications` に作成されます。

```
~/Applications/Hollow Knight - Silksong.app
└── Contents
    ├── Info.plist                 # SteamShelfAppID マーカー + ゲーム情報
    ├── MacOS/run.sh               # open "steam://rungameid/1030300"
    └── Resources/icon.icns        # ゲームのカバーアートから生成
```

ファイル名に使えない文字は置き換えられます。`Hollow Knight: Silksong` は `Hollow Knight - Silksong.app` になりますが、Spotlight ではそのまま名前で見つかります。

### 何に触れるのか

同期が自分のものとして認識するバンドルは次の 2 種類だけです。

| 種類 | 判別方法 |
|---|---|
| Steam Shelf が作成したもの | `Info.plist` の `SteamShelfAppID` キー |
| Steam の「Add to Applications」が作成したもの | `run.sh` 内の `autogenerated file` マーカーと `steam://run` URL |

`~/Applications` にあるそれ以外のアプリには一切手を付けません。ゲームが使いたい名前を通常のアプリが既に占有している場合は、上書きせずにスキップして結果に報告します。アンインストール済みゲームのショートカットはゴミ箱へ移動するので、いつでも復元できます。

## 仕組み

| 項目 | 方法 |
|---|---|
| ライブラリの探索 | `steamapps/libraryfolders.vdf` を解析してすべてのライブラリルートを取得 |
| ゲームの列挙 | 各 `appmanifest_*.acf` から appid・名前・容量・最終プレイ日時を解析 |
| インストール判定 | `steamapps/common/<installdir>` の実在を必須とし、ダウンロード待ちの項目を除外 |
| カバーアート | `appcache/librarycache/<appid>` 配下で `library_600x900` / `library_capsule` / `library_header` を探索し、無ければ Steam CDN から取得して `~/Library/Application Support/SteamShelf/covers` にキャッシュ |
| 起動 | `steam://rungameid/<appid>` |
| 自動更新 | `DispatchSource` で各 `steamapps` フォルダを監視し、変更時に再読み込み |
| アイコン | カバーアートを正方形に切り出し、ImageIO で `.icns` を書き出し |

```
  App.swift            アプリのエントリポイントとメニューコマンド

```

## FAQ

### Steam は起動したままにする必要がありますか？

はい。Steam Shelf は Steam を迂回しません。クライアントでプレイボタンを押すのとまったく同じように、Steam に起動を依頼します。そのおかげでクラウドセーブ、実績、プレイ時間、オーバーレイが正常に機能します。Steam が起動していない場合は自動的に立ち上がります。

### 「ショートカット同期」を実行しても安全ですか？

削除対象になるのは Steam Shelf のマーカー、または Steam 自身の autogenerated マーカーを持つバンドルだけで、削除といってもゴミ箱への移動です。他のアプリには `Info.plist` を読む以外に触れません。

### カバーアートはどこから来ますか？

Steam が既にライブラリアートワークをディスクにキャッシュしているため、まずそこを参照します。この場合ネットワークは一切使いません。ローカルにアートが無いゲームだけが Steam CDN から一度ダウンロードされます。

### なぜ macOS 14 以降なのですか？

UI が Sonoma で追加された SwiftUI API を使用しています。デプロイメントターゲットを下げるにはツールバーとウィンドウ処理の大部分を作り直す必要があり、得られるものに対して割に合いません。

### Steam 以外のゲームには対応していますか？

現時点では対応していません。Steam Shelf は Steam のマニフェストを読むため、Steam でインストールしたゲームのみが表示されます。セカンダリライブラリや外付けドライブ上の Steam ゲームは完全にサポートしています。
