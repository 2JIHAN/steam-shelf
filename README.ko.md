Steam Shelf는 로컬 Steam 라이브러리를 읽어 설치된 모든 게임을 커버아트 그리드로 보여줍니다. 타일을 클릭하면 바로 실행됩니다. 한 번 더 클릭하면 게임마다 실제 `.app` 번들을 `~/Applications`에 만들어, Launchpad와 Spotlight에서 다른 앱들과 나란히 게임을 띄울 수 있습니다. Steam 창을 거칠 필요가 없습니다.

외부 의존성 없는 단일 SwiftUI 바이너리이며, `swiftc` 한 번으로 빌드됩니다. 열어야 할 Xcode 프로젝트도 없습니다.

<!-- 스크린샷 자리: docs/screenshot.png -->

## 주요 기능

- **커버아트 그리드** — Steam이 이미 받아둔 로컬 캐시를 쓰므로 오프라인에서도 동작합니다. 없는 아트만 Steam CDN에서 한 번 받아 캐시합니다.
- **클릭 한 번으로 실행** — 타일은 공식 실행 경로인 `steam://rungameid/<appid>`를 엽니다. 클라우드 세이브, 플레이 시간, 오버레이가 모두 평소대로 동작합니다.
- **게임별 `.app` 바로가기** — 설치된 게임을 커버아트 아이콘과 함께 `~/Applications`에 동기화합니다. Launchpad·Spotlight에서 바로 실행됩니다.
- **안전한 정리** — 삭제된 게임의 바로가기는 완전 삭제가 아니라 휴지통으로 이동합니다. Steam Shelf가 스스로 관리한다고 증명할 수 있는 번들만 건드립니다.
- **실시간 반영** — `steamapps` 폴더를 감시하므로 게임을 설치하거나 지우면 재시작 없이 그리드가 갱신됩니다.
- **다중 라이브러리** — `libraryfolders.vdf`를 따라 외장 드라이브와 보조 라이브러리 폴더까지 읽습니다.
- **검색과 정렬** — 이름으로 필터링하고, 최근 플레이·이름·용량 순으로 정렬합니다.

## 설치

소스에서 빌드합니다.

```bash
git clone https://github.com/2JIHAN/steam-shelf.git
cd steam-shelf
./build.sh
```

`~/Applications/Steam Shelf.app`에 설치됩니다. 다른 위치에 설치하려면 경로를 넘기세요.

```bash
./build.sh /Applications
```

빌드 결과물은 ad-hoc 서명됩니다. 직접 컴파일했으므로 격리(quarantine) 속성이 붙지 않아 Gatekeeper가 막지 않습니다. 압축 파일이나 다운로드를 거쳐 앱을 옮겼다면 다음으로 속성을 제거하세요.

```bash
xattr -dr com.apple.quarantine "/Applications/Steam Shelf.app"
```

## 바로가기 동기화

<kbd>⇧</kbd><kbd>⌘</kbd><kbd>S</kbd>를 누르거나 툴바 버튼을 클릭하면, 설치된 게임마다 `.app` 번들이 `~/Applications`에 만들어집니다.

```
~/Applications/Hollow Knight - Silksong.app
└── Contents
    ├── Info.plist                 # SteamShelfAppID 마커 + 게임 메타데이터
    ├── MacOS/run.sh               # open "steam://rungameid/1030300"
    └── Resources/icon.icns        # 게임 커버아트로 생성
```

파일 이름에 쓸 수 없는 문자는 치환됩니다. `Hollow Knight: Silksong`은 `Hollow Knight - Silksong.app`이 되지만 Spotlight 검색에는 지장이 없습니다.

### 무엇을 건드리는가

동기화가 자기 것으로 인식하는 번들은 두 종류뿐입니다.

| 종류 | 식별 방법 |
|---|---|
| Steam Shelf가 만든 것 | `Info.plist`의 `SteamShelfAppID` 키 |
| Steam의 "Add to Applications"가 만든 것 | `run.sh` 안의 `autogenerated file` 마커 + `steam://run` URL |

`~/Applications`의 나머지 앱은 건드리지 않습니다. 게임이 쓰려는 이름을 일반 앱이 이미 차지하고 있으면 덮어쓰지 않고 건너뛴 뒤 결과에 표시합니다. 삭제된 게임의 바로가기는 휴지통으로 가므로 언제든 복구할 수 있습니다.

## 동작 원리

| 항목 | 방식 |
|---|---|
| 라이브러리 탐색 | `steamapps/libraryfolders.vdf`를 파싱해 모든 라이브러리 루트 수집 |
| 게임 목록 | 각 `appmanifest_*.acf`에서 appid, 이름, 용량, 최근 플레이 시각 파싱 |
| 설치 판정 | `steamapps/common/<installdir>`의 실제 존재 여부를 요구해 다운로드 대기 항목 제외 |
| 커버아트 | `appcache/librarycache/<appid>` 아래에서 `library_600x900` / `library_capsule` / `library_header`를 찾고, 없으면 Steam CDN에서 받아 `~/Library/Application Support/SteamShelf/covers`에 캐시 |
| 실행 | `steam://rungameid/<appid>` |
| 자동 갱신 | `DispatchSource`로 각 `steamapps` 폴더를 감시해 변경 시 재로딩 |
| 아이콘 | 커버아트를 정사각으로 크롭해 ImageIO로 `.icns` 작성 |

## 프로젝트 구조

```
Sources/
  App.swift            앱 진입점, 메뉴 명령
  ContentView.swift    그리드 UI와 게임 타일
  Store.swift          상태 관리, 커버 로딩, 폴더 감시
  SteamLibrary.swift   라이브러리·매니페스트 스캔
  Artwork.swift        커버 조회, CDN 폴백, .icns 생성
  ShortcutSync.swift   .app 바로가기 생성과 정리

make_icon.swift        앱 아이콘 생성기 (.icns / .png)
build.sh               빌드 스크립트
```

## 자주 묻는 질문

### Steam이 계속 실행되어 있어야 하나요?

네. Steam Shelf는 Steam을 우회하지 않습니다. 클라이언트에서 플레이 버튼을 누르는 것과 똑같이 Steam에 실행을 요청합니다. 그래야 클라우드 세이브, 도전 과제, 플레이 시간, 오버레이가 정상 동작합니다. Steam이 꺼져 있으면 자동으로 켜집니다.

### 바로가기 동기화를 눌러도 안전한가요?

Steam Shelf 마커나 Steam의 autogenerated 마커가 있는 번들만 제거 대상이며, 제거는 휴지통 이동입니다. 다른 앱은 `Info.plist`를 읽는 것 외에 전혀 손대지 않습니다.

### 커버아트는 어디서 오나요?

Steam이 이미 라이브러리 아트워크를 디스크에 캐시해 두므로 이를 먼저 확인하고, 이 경우 네트워크를 전혀 쓰지 않습니다. 로컬 아트워크가 없는 게임만 Steam CDN에서 한 번 내려받습니다.

### 왜 macOS 14 이상인가요?

UI가 Sonoma에서 도입된 SwiftUI API를 사용합니다. 배포 타깃을 낮추려면 툴바와 윈도우 처리 상당 부분을 다시 구현해야 하는데, 얻는 것에 비해 비용이 큽니다.

### Steam 외 게임도 지원하나요?

현재는 아닙니다. Steam Shelf는 Steam의 매니페스트를 읽으므로 Steam으로 설치한 게임만 나타납니다. 보조 라이브러리나 외장 드라이브의 Steam 게임은 완전히 지원합니다.
